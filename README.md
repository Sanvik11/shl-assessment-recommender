# Conversational Assessment Recommender

A conversational agent that takes a hiring manager from a vague intent
("I'm hiring a Java developer") to a grounded shortlist of SHL Individual
Test Solutions through dialogue — with clarification, refinement, grounded
comparison, and strict scope/hallucination guardrails.

AI-powered conversational assessment recommender built using FastAPI, retrieval-augmented generation (RAG), and Google's Gemini API.

## Architecture

```
User turn (full history) ──▶ FastAPI /chat
                                  │
                    guardrails: injection / off-topic?
                                  │  (no)
                                  ▼
                    retrieval: embed query, search catalog
                    (Gemini text-embedding-004 + FAISS,
                     or TF-IDF fallback with no API key)
                                  │
                    candidates (numbered list, catalog-only)
                                  │
                                  ▼
                    LLM picks an action (clarify / recommend /
                    refine / compare) + selected_indices
                    — never a free-text name or URL
                                  │
                                  ▼
                    agent.py materializes Recommendation
                    objects strictly from the catalog by index
                                  │
                                  ▼
                    { reply, recommendations, end_of_conversation }
```

**Key design decision — indices, not names.** The model never outputs an
assessment name or URL directly. It only ever selects numeric indices into
a candidate list we built from the catalog via retrieval. `agent.py` then
looks up the real `Assessment` objects by index. This makes a hallucinated
catalog entry structurally impossible, rather than just "discouraged by the
prompt" — which is the #1 failure mode the assignment brief calls out.

**Key design decision — state lives in the reply text.** The API is
stateless: every `/chat` call gets the full message history, but only
`role`/`content` round-trips — not our structured `recommendations` array.
So every "recommend"/"refine" reply names the shortlisted assessments
inline in the `reply` string (e.g. *"Here are assessments that fit: Spring
(New), Core Java..."*). That's what lets a later turn recover "we already
gave a shortlist, this is a refinement" purely from plain conversation
text, with no server-side session store.

**Two interchangeable backends**, selected via `LLM_PROVIDER`/`GEMINI_API_KEY`:
- `GeminiBackend` + `GeminiFaissRetriever` — production path. Gemini
  2.0 Flash for structured JSON generation, Gemini `text-embedding-004` +
  FAISS (`IndexFlatIP` over L2-normalized vectors = cosine similarity) for
  retrieval.
- `OfflineBackend` + `TfidfRetriever` — deterministic, no network calls,
  used automatically when no `GEMINI_API_KEY` is set. This is what makes
  the project runnable and testable without any external dependency, and
  is what the included test suite runs against.

## Project layout

```
app/
  schemas.py     Pydantic models — the exact request/response contract
  catalog.py     Loads data/catalog.json (or data/catalog_seed.json)
  retriever.py   TfidfRetriever (offline) / GeminiFaissRetriever (prod)
  llm.py         OfflineBackend (rule-based) / GeminiBackend (structured JSON)
                 + shared guardrail regexes (injection/off-topic detection)
  agent.py       Orchestration: guardrails → retrieval → backend → response
  main.py        FastAPI app: GET /health, POST /chat
data/
  catalog_seed.json   22 real, individually verified SHL assessments
                       (name/url/test_type/description/levels/duration)
                       — ships in the repo so the app runs out of the box
  catalog.json        Full scraped catalog (generated by the scraper,
                       gitignored — see "Getting the full catalog" below)
  build_index.py      Standalone script to build+sanity-check the Gemini
                       FAISS index against data/catalog.json
scraper/
  scrape_catalog.py   Crawls shl.com's product catalog (Individual Test
                       Solutions only) into data/catalog.json
tests/
  test_agent.py       9 tests: schema compliance, no-hallucination guard,
                       clarify/recommend/refine/compare/refuse behaviors
```

## Running locally

```bash
pip install -r requirements.txt

# Offline mode (no API key, no network calls) — good for dev/CI:
uvicorn app.main:app --reload

# Production mode (Gemini-powered):
export GEMINI_API_KEY=your_key_here
uvicorn app.main:app --reload
```

Then:
```bash
curl http://localhost:8000/health
curl -X POST http://localhost:8000/chat \
  -H "Content-Type: application/json" \
  -d '{"messages":[{"role":"user","content":"Hiring a Java developer who works with stakeholders"}]}'
```

## Getting the full catalog

This project was built in a sandboxed environment whose outbound network
only allowlists package registries (PyPI, npm, GitHub) — it cannot reach
`shl.com`. So `data/catalog_seed.json` was assembled from real, individually
verified SHL catalog pages, not a live crawl, and intentionally ships small
(22 entries) rather than padded with invented ones.

`scraper/scrape_catalog.py` is a complete, ready-to-run BeautifulSoup
scraper for the real thing. Run it anywhere with normal internet access:

```bash
python scraper/scrape_catalog.py --out data/catalog.json
```

It paginates the listing page, follows every `/product-catalog/view/...`
link, and parses name/test-type/description/job-levels/duration off each
detail page. Once `data/catalog.json` exists, `Catalog.load()` picks it up
automatically (it's preferred over the seed file — see `app/catalog.py`).
Then optionally rebuild/sanity-check the Gemini index:

```bash
export GEMINI_API_KEY=your_key_here
python data/build_index.py
```

## Testing

```bash
python -m pytest tests/ -v
```

Runs fully offline (forces `LLM_PROVIDER=offline`) so it needs no API key —
this is also what's asked for in the brief's "evaluation rigor" section:
realistic multi-turn conversations plus explicit hallucination/schema checks.

## Deploying

Any ASGI-friendly free host works (Render, Fly.io, Railway, Modal, HF
Spaces). Minimal `Procfile`/start command:

```
uvicorn app.main:app --host 0.0.0.0 --port $PORT
```

Set `GEMINI_API_KEY` in the host's env vars for the production backend.
Cold-start hosts are fine — the brief allows up to 2 minutes for the first
`/health` call to wake the service.
